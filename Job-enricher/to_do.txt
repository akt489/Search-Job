Fix "inconsistent types deduced for parameter $1" in the enricher
Context:
Job-enricher is a Node.js ESM worker that updates rows in a Postgres jobs table. Grants are correct. But running npm start fails with:

text
{"level":50,"event":"job_enrichment_failed","jobId":14,
 "error":"inconsistent types deduced for parameter $1",
 "msg":"Job enrichment failed"}

{"level":50,"event":"job_failure_update_failed","jobId":14,
 "error":"inconsistent types deduced for parameter $1",
 "msg":"Could not mark job failed"}
The worker stops after this error.

What I need you to do:

Read the update SQL. Look in src/worker.js, src/db/*.js, or wherever UPDATE jobs SET appears. Find:

The enrichment result update (sets title, title_en, company, location, salary, category, type, experience_level, deadline, application_url, requirements, description_en, enrichment_status, enriched_at, ai_model)

The failure update (sets enrichment_status='failed', enrichment_error, enriched_at)

Identify why Postgres reports inconsistent types deduced for parameter $1. This error means the same $N placeholder is used in two contexts that imply different types. Common causes:

$1 used as both text and jsonb (e.g., for requirements)

$1 used with COALESCE/NULLIF where Postgres can't infer type

Parameter array order doesn't match placeholder positions

JSONB column receiving a value without a cast

Fix the SQL by doing all of the following:

Add explicit type casts to every parameter: $1::text, $5::jsonb, $3::timestamptz, etc.

For JSONB columns (specifically requirements), always cast: $N::jsonb. The driver sends JS objects/arrays as text; without the cast Postgres can't decide.

For nullable text fields, use NULLIF($N::text, '') to convert empty strings to NULL.

Never reuse a parameter index across different column types. Each $N maps to exactly one value in the array, used in exactly one type context.

Fix the job-selection query so it never picks jobs that have no source text:

Change LEFT JOIN job_sources to INNER JOIN job_sources so only jobs with at least one source row are claimed.

This prevents the worker from trying to enrich seed/test jobs (like jobId: 14) that have no raw_text — those were what triggered the failure.
